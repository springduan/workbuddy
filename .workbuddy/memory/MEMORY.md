# WorkBuddy 项目记忆

**工作背景**
商务车排班系统 WorkBuddy 的开发者，技术栈为 Windows + Node.js。用户作为汽车运输从业者，长期担任商务车服务乙方，同时运营贵阳白云巴士小红书蓝V账号。当前正推进排班系统的功能迭代，涵盖航班/高铁准点延误取消标签（含延误时间输入）、排班页面多状态筛选、车辆安排选项及弹窗信息优化，以及企业微信配置功能的开发。

**个人背景**
中文交流为主，沟通风格偏好截图驱动的迭代式 UI 优化方式，重视具体视觉反馈而非纯文字描述。在业务实践中面临服务标准认定争议及压缩用车导致司机情绪等合同问题，正准备向白云巴士客运公司提交自荐 PPT 方案。**不熟悉服务器管理和 PM2 操作**，涉及服务器运维时需给详细步骤。

**排班规则**
- 飞机出发提前量60分钟，高铁出发提前量40分钟
- 飞机趟次间隔150分钟，高铁趟次间隔100分钟
- 每辆车趟数均衡分配，交通类型（机场/高铁）均衡分配

**代码修复记录 (2026-04-26)**
- 预计用车算法：与实际排班算法保持一致，使用正确的出发提前量和趟次间隔
- 预计用车算法（第二次修复）：时间间隔判断改为「下一趟出发 - 上一趟出发 >= 上一趟往返耗时」，与实际排班完全一致
- 排班算法时间间隔检查修复：从只检查最后一趟改为双向检查（后向：与时间上最近的前一趟比较；前向：与时间上最近的后一趟比较），修复客户时间早于已有任务时被误判为冲突的问题
- 预计算法同步修复：记录每辆车所有已分配任务的出发时间和往返耗时，同样进行双向间隔检查
- 甘特图时间显示：使用returnTime作为结束时间，而非arrivalTime+30分钟
- 排班方案表格：新增"返回时间"列
- 甘特图Tooltip：新增"返回时间"字段
- 车辆不足提示：使用实时计算的estimatedVehiclesPreview
- 清理未使用代码：删除avgTripsPerVehicle、taskEndMinutes等
